# 人员关系与业务标签智能查询：能力与需求差距说明

> 对照文档：《人员关系与业务标签智能查询 Agent_查询需求说明》  
> 对照实现：`identity-mcp` + Skill `person-relation-tag-query`（v0.2.0）  
> 对照实测：桌面《测试结果：.md》（涉华/在华教育/高科技·高通/政客/多轮/排除）  
> 日期：2026-09-10

---

## 1. 我们现在能做什么（V1 已具备）

| 能力 | 现状 | 实测结论 |
|------|------|----------|
| 自然语言 → 结构化检索 | Skill 引导 + `search_persons` | 宽查询会先澄清或走默认「涉华+现居美国」 |
| 涉华/涉台/涉港标签 | 查询时推导（工作/求学在目标地），不入库 | 有硬证据时可交付样本中的符合项 |
| 教育/工作经历国家 | `edu_country` / `work_country` | 「在华教育+现居美国」20 条中约 19 条真有在华学历 |
| 现居国家 | `location_country`（仅现居字段） | 与历史 `countries[]` 已拆开，现居过滤有效 |
| 机构/企业关键词 | `company_keyword` / `school_keyword` | 「在华教育+高通」可出名单（命中量可低于护栏） |
| 行业组合 | `industry_keywords`（默认当前 industry） | 「高科技」需人工按 `industry` 复核，曾有跨段误配 |
| 多条件 AND | ES filter 默认 AND | 可用 |
| 二次筛选 / 多轮 | `include_ids` / `exclude_ids`（≤200） | 三连多轮可跑通；终值是样本下界 |
| 条件排除 | `exclude_edu_country`、`exclude_retired`、差集+`exclude_ids` | 「涉华 NOT 在华教育」「NOT 退休」可做 |
| 精确核验 | `lookup_by_name` / linkedin / unique_id | 政客场景下比群体关键词可靠 |
| 结果可读性 | `education_brief` / `experience_brief` / `evidence_flags` | 便于「符合/存疑/排除」三段输出 |

**明确不宣称：** 全量涉华名单、民选政客完备库、访华记录、共同经历、人→企→人多跳。

## 2. 与需求文档的差距一览

| 需求章节 | 需求要点 | 差距等级 | 说明 |
|----------|----------|----------|------|
| 一、建设目标 | NL 查询 + 多轮关联 + 结果汇总 | **部分满足** | 单轮/浅多轮可用；深关联未做 |
| 二、涉华/台/港对象 | 含「曾访问」、机构合作、企业关联等 | **部分满足** | 经历类可推；访问/合作边缺失 |
| 三、基础查询「查涉华」 | 直接出符合列表 | **弱** | 只能样本+澄清，不能全量枚举 |
| 四、教育/工作/机构经历 | 在华港台教育与工作；高校任职；高科技企业 | **大部分满足** | 国家经历 OK；「高校/高科技」靠关键词非分类体系 |
| 五、标签组合 | 高科技、高通、美国政客等 | **部分满足** | 高通较好；高科技需复核；政客群体检索失败 |
| 六、多条件 AND | 全部条件同时成立 | **满足** | — |
| 七、AND/OR/NOT | 含 OR、自然语言排除 | **不足** | AND/差集 NOT 有；真 OR 无一等公民 |
| 八、二次查询 | 以上轮结果为集合继续筛 | **部分满足** | 有 `include_ids`，但池≤20×N 且会话无持久化 |
| 九、上下文记忆 | 「其中/这些人」指代 | **弱** | 靠对话模型记忆，无独立结果集存储 |
| 十、多级关联 | 人→机构→其他人 | **未做** | Skill 明确 V1 不做 |
| 十一、共同内容 | 多人共同教育/任职/企业 | **未做** | Skill 明确 V1 不做 |
| 十二、条件修改/切换 | 改类型而非盲目叠加 | **规则有、无状态机** | 依赖模型遵守 Skill |

文件夹名含「组织查询」：当前 **无独立组织库/组织 MCP**，本文档需求也以人员为主。

## 3. 差距出现的原因

### 3.1 数据层（主因）

| 缺失/缺陷 | 影响的需求 |
|-----------|------------|
| **无访华/出行记录字段** | 「曾访问中国/台/港」无法回答 |
| **无预打业务标签**；经历 `location` 大量 null | 涉华只能推导，漏检+误报并存 |
| **experience/education 非 nested** | 行业×职位跨经历段误配（实测高科技误命中 translation 等） |
| **退休经历段 country 常被填成 china** | 「涉华退休者」大量假阳性 |
| **民选政客/公众人物覆盖极少** | 「涉华美国政客」群体检索几乎必然失败（库内更像助理/外交/学生） |
| **无机构类型/高校名录/合作关系边** | 「中国高校任职」「机构关联人员」只能关键词近似 |
| **无结构化「退休」字段** | NOT 退休只能靠 title 含 retired 近似 |
| **索引体量极大（亿级）** | 宽条件动辄 >10000，只能采样，无法「全量名单」 |
| **skills/摘要体积大** | 一次 size 过大导致工具输出截断、`unique_id` 丢失、多轮链断裂（已强制 size≤20 并瘦身字段） |

### 3.2 产品/实现层

| 原因 | 影响 |
|------|------|
| V1 范围主动砍掉多跳与交集 | 需求十、十一空白 |
| 业务标签写死在代码（涉华/台/港） | 与「可配置标签体系」不符 |
| 无会话结果集服务 | 上下文记忆、二次筛选上限与可靠性不足 |
| 无 OR 查询建模 | 「满足任一」需多次查询手工并集 |
| 组织侧未建 MCP | 「组织查询」无法验收 |

### 3.3 能力边界（工具链）

| 原因 | 影响 |
|------|------|
| 纯离线领英画像，无联网补全 | 政客/名人名单、最新任职、非领英人物缺口大 |
| 单次返回 ≤20、include_ids ≤200 | 与「列表交付/多轮深挖」体感有落差 |
| 排除曾依赖弱关键词 | 已补 `exclude_edu_country` / `exclude_retired`，但仍非完备逻辑引擎 |

## 4. 解决方案建议（按优先级）

### P0 — 口径与验收对齐（不改库也能做）

1. **需求说明书增加「V1 范围」**：标明曾访问、共同经历、多跳、全量涉华名单、民选政客完备检索为后续或不可用。  
2. **对外话术统一**：`is_sample` = 非全量样本；有硬证据仍交付「本批符合项」。  
3. **政客/名人类问题标准路径**：外部名单（或联网搜索）→ `lookup_by_name` 核验；禁止只靠 senator 等词。

### P1 — 增强现有 MCP/Skill（短期）

| 方案 | 作用 |
|------|------|
| ~~瘦身返回 + size≤20~~ | 已做，防多轮断链 |
| ~~`exclude_edu_country` / `exclude_retired` / `evidence_flags`~~ | 已做 |
| ~~行业默认当前字段~~ | 已做 |
| ~~`search_after` 分页 + `include_ids`≤500 + `condition_logic` + `exclude_work_country`~~ | 已做（2026-09-21，Skill v0.3.0） |
| **结果集会话存储**（Redis/DB：session→unique_id[]） | 真正「上下文记忆」、可超 500 分页二次筛 |
| **标签规则外置 YAML** | 可配置业务标签体系 |


### P2 — 补数据与旁路能力（中期）

| 方案 | 作用 |
|------|------|
| **联网搜索 / 公开资料** 生成政客、高管、学者候选名单，再回库核验 | 弥补公众人物覆盖 |
| **高校/央企/科技企业名录** 作机构锚点词典 | 「中国高校任职」「高科技企业」可硬匹配 |
| **清洗退休段 country 伪填** 或入库时打 `is_retired` | 降假阳性 |
| **education/experience 改为 nested 或拆宽表** | 根治跨段误配 |
| **访华/行程数据源**（若业务强需求） | 曾访问类问题 |
| **组织实体索引 + 人企边** | 组织查询、多跳关联 |

### P3 — 需求十/十一专用能力（中长期）

1. **共同经历工具**：输入 N 个 `unique_id`，对 education.school / experience.company 求交集。  
2. **关联扩展工具**：由人取机构列表 → 再 `company_keyword`/`school_keyword` 查其他人（受控跳数、护栏）。  
3. **条件栈状态机**：增/删/改/替换条件，避免「不要政客却 AND 高管」类错误。

## 5. 实测对照摘要（便于复验）

| 用例 | 结果摘要 | 根因归类 |
|------|----------|----------|
| 涉华人员（默认+美国） | 20 样本中约 14 条有硬证据 | 数据可查；全量不可枚举 |
| 在华教育+现居美国 | 约 19/20 真有在华学历 | 能力达标（样本级） |
| 在华教育+高科技 / +高通 | 高科技需剔除非科技 industry；高通可出名单 | 行业弱匹配 / 机构词相对可靠 |
| 涉华美国政客 | 群体检索无民选官员；精确核验仅个别议员且常无在华履历 | **数据覆盖** |
| 多轮三连 | 可跑通；size 过大曾断链 | 已用 size≤20+瘦身缓解 |
| NOT 在华教育 / NOT 退休 | 差集与 exclude 可用；退休 country 伪信号严重 | **数据质量** + 已提供排除参数 |

---

## 6. 结论

当前 V1 适合作为 **「离线领英画像上的经历/现居/机构关键词筛选 + 浅多轮收窄」** 助手，不适合直接按需求文档验收为 **「完备业务标签 + 多跳图谱 + 共同经历 + 访华」** 系统。

差距主因是 **数据模型与覆盖**，其次是 **V1 未做多跳/交集** 与 **无结果集中台**。短期靠口径管理、精确核验、联网补名单、会话结果集即可明显提升可用性；中长期再补名录、清洗、nested/边关系与组织库。
