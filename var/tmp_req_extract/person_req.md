人员关系与业务标签智能查询 Agent
查询需求说明
面向离线人员数据库的自然语言智能查询与多轮关联分析
一、建设目标
建设面向离线人员数据库的智能问答查询 Agent，通过自然语言理解用户查询意图，将用户提出的人员筛选条件转换为数据库查询条件，从离线库中检索符合要求的人员，并以结构化列表形式输出。
Agent 不仅支持单次查询，还应支持基于上一轮查询结果的二次筛选、连续追问、条件叠加、条件排除和多轮关联查询。
核心能力：自然语言提问 → 意图识别 → 条件解析 → 数据库检索 → 人员列表 → 二次筛选 → 多轮关联查询 → 结果汇总。
二、查询对象
1. 涉华人员
涉华人员
与中国存在关联的人员
曾访问中国的人员
在华工作、学习人员
与中国机构存在任职或合作关系的人员
与中国企业存在关联的人员
2. 涉台人员
涉台人员
曾访问台湾地区的人员
在台有工作经历人员
在台有教育经历人员
与台湾机构存在关联人员
3. 涉港人员
涉港人员
曾访问香港的人员
在港有工作经历人员
在港有教育经历人员
与香港机构存在关联人员
说明：涉华、涉台、涉港应作为可配置的业务标签体系，而非固化在 Agent 业务逻辑中。
三、基础查询能力
Agent 应支持用户通过自然语言直接提出人员查询需求，并自动识别查询对象、业务标签、地域、身份、经历等条件，调用离线数据库完成检索。
示例：查询涉华人员。
处理流程：识别对象=人员；业务标签=涉华；执行数据库检索；输出符合条件的人员列表。
四、人员经历条件查询
1. 教育经历
查询在华有教育经历的人员。
查询在香港有教育经历的人员。
查询在台湾有教育经历的人员。
2. 工作经历
查询在华有工作经历的人员。
查询在香港有工作经历的人员。
查询在台湾有工作经历的人员。
3. 机构经历
查询曾经在中国高校任职的人员。
查询与中国高科技企业有工作经历的人员。
五、业务标签组合查询
Agent 应支持业务标签、人员属性、地域及经历条件的组合查询。
示例：查询在华有教育经历的高科技人员。
条件：人员对象=人员；地域=中国；经历类型=教育经历；业务标签=高科技。
示例：查询在华有教育经历的高通人员。
条件：地域=中国；经历类型=教育经历；机构/企业=高通。
示例：查询涉华的美国政客。
条件：国籍=美国；人员类型=政客；业务标签=涉华。
六、多条件 AND 查询
支持多个条件同时成立，并确保最终人员满足全部条件。
示例：查询美国政客中涉华且在华有教育经历的人员。
美国 AND 政客 AND 涉华 AND 在华教育经历
示例：查询涉华、在中国工作过，并且属于高科技领域的人员。
涉华 AND 在华工作经历 AND 高科技
七、条件排除查询
支持 AND、OR、NOT，以及“包含、不包含、满足任一条件、同时满足多个条件”等自然语言表达。
示例：涉华 AND 美国政客 AND NOT 在华教育经历
示例：涉华 AND NOT 退休
八、二次查询能力
第一次查询得到人员列表后，用户可以基于第一次结果继续提问，Agent 应自动将上一轮结果作为当前查询的基础集合。
第一轮：查询涉华的美国政客。→ 人员集合 A
第二轮：筛选其中在华有教育经历的人。→ A AND 在华教育经历
第三轮：再筛选出其中与高科技企业有关联的。→ B AND 高科技企业关联
九、上下文记忆能力
Agent 应具备查询上下文记忆，能够识别“其中、这些人、他们、再筛选、继续、排除”等指代关系，并保留当前查询集合及已使用条件。
第一轮：查询涉华人员。
第二轮：其中有哪些美国人？
第三轮：其中有在华教育经历的吗？
第四轮：再看看他们有没有高科技行业经历。
十、多次关联查询
支持跨人员、跨机构、跨经历的多级关联查询，并允许查询对象随问题变化。
人员 → 人员经历 → 教育机构/工作机构 → 机构关联人员
示例：查询涉华美国政客 → 查询其中在中国高校就读者 → 查询这些人曾任职的高科技企业 → 查询这些企业关联的其他涉华人员。
十一、共同内容查询
支持对多个目标人员进行集合交集分析，寻找共同的教育经历、任职机构、企业、访问地点或其他共同属性。
找出这几个人共同的教育经历。
这些人共同任职过哪些机构？
这些人有没有共同关联的企业？
找出这些人的共同经历。
十二、互斥条件与查询条件调整
Agent 应判断用户是在增加条件、修改条件、删除条件、排除条件、重新查询，还是切换查询对象。
例如：第一轮查询在华有教育经历人员；第二轮查询其中美国政客；第三轮说“不要政客，看看企业高管”，应理解为修改/切换人员类型，而非简单叠加为“政客 AND 企业高管”。
