# 组织人员离线库接口文档

任务状态：`running`（进行中）→ `end`（正常结束） / `cancelled`（取消） / `failed`（失败）

---

### 一、新建会话接口

请求方式：POST  http://192.168.3.171:8088/api/chat/sessions

返回参数：

```json
{
    "createdAt": 1793607136102,
    "sessionId": "sess_58527fa3f6e445c79deda22e3c970486",
    "hermesSessionId": "api_1793607136_2a9f6a06"
}
```

说明：取 `sessionId` 给问答接口用。

---

### 二、问答

请求方式：POST http://192.168.3.171:8088/api/chat/ask

请求参数：

```json
{
    "sessionId": "sess_58527fa3f6e445c79deda22e3c970486",
    "userId": "u001",
    "message": "查询一下涉华美国智库"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| sessionId | 否 | 不传则自动新建会话 |
| userId | 否 | 用户标识，写入历史用 |
| message | 是 | 提问内容 |

返回参数：

```json
{
    "sessionId": "sess_58527fa3f6e445c79deda22e3c970486",
    "hermesSessionId": "api_1793607136_2a9f6a06",
    "taskId": "task_a1b2c3d4e5f6478899aabbccddeeff00",
    "userId": "u001",
    "status": "running",
    "hint": "流式输出：GET /api/chat/tasks/task_xxx/stream"
}
```

说明：接口立即返回，`status` 为 `running`。取 `taskId` 去订阅流式、查任务或取消。

---

### 三、订阅流式输出（SSE）

请求方式：GET http://192.168.3.171:8088/api/chat/tasks/{taskId}/stream

Content-Type 为 `text/event-stream`。主要事件：（渲染思考过程和最终回答即可）

| event | 说明 |
|-------|------|
| connected | 订阅成功 |
| status | 任务状态，如 `{"status":"running"}` / `end` / `cancelled` / `failed` |
| reasoning.delta | 思考过程增量（中文） |
| assistant.delta | 最终回答增量 |
| tool.started / tool.completed | 工具调用起止 |
| cancelled | 任务被取消 |
| error | 失败信息 |
| stream_end | 本轮流结束 |

示例（片段）：

```text
event: connected
data: {"taskId":"task_xxx","sessionId":"sess_xxx"}

event: status
data: {"status":"running"}

event: reasoning.delta
data: {"delta":"用户要查涉华美国智库..."}

event: assistant.delta
data: {"delta":"根据检索结果..."}

event: status
data: {"status":"end"}

event: stream_end
data: {"ok":true}
```

---

### 四、取消任务

请求方式：POST http://192.168.3.171:8088/api/chat/cancel

按 taskId 取消：

```json
{
    "taskId": "task_a1b2c3d4e5f6478899aabbccddeeff00"
}
```

按 sessionId 取消该会话下所有进行中任务：

```json
{
    "sessionId": "sess_58527fa3f6e445c79deda22e3c970486"
}
```

返回参数：

```json
{
    "ok": true,
    "cancelledCount": 1,
    "skippedCount": 0,
    "cancelled": [
        {
            "taskId": "task_a1b2c3d4e5f6478899aabbccddeeff00",
            "sessionId": "sess_58527fa3f6e445c79deda22e3c970486",
            "statusBefore": "running",
            "cancelled": true,
            "status": "cancelled"
        }
    ],
    "skipped": []
}
```

说明：`taskId` 与 `sessionId` 至少传一个。取消后任务状态变为 `cancelled`，流里会收到 `cancelled` 与 `stream_end`。

### 五、历史记录（GraphQL）

请求方式：POST http://192.168.3.171:8088/graphql

调试页：http://192.168.3.171:8088/graphiql

#### 5.1 会话历史列表 getChatHistory

默认按 sessionId 聚合：每个会话只返回最新一轮问答（含 `turnCount` 总轮数），按 add_date 倒序。
参数：`userId`（可选，精确）、`keyword`（可选，模糊匹配问题/回答）、`pageNo`、`pageSize`（≤100）。`totalCount` 为会话数。

```graphql
query {
  getChatHistory(userId: "test001", keyword: "", pageNo: 1, pageSize: 10) {
    code
    message
    totalCount
    totalPage
    records
  }
}
```

#### 5.2 会话详情 getChatSessionDetail

按 sessionId 聚合该会话下全部问答，按 add_date 升序（对话时间线）。
`records` 为对象：`sessionId`、`userId`、`title`（首轮问题）、`turnCount`、`firstAddDate`、`lastAddDate`、`turns[]`（每轮含 task_id/question/content/add_date）。会话不存在时 `code=404`。

```graphql
query {
  getChatSessionDetail(sessionId: "sess_58527fa3f6e445c79deda22e3c970486") {
    code
    message
    totalCount
    records
  }
}
```

说明：问答结束后会写入 ES（索引 sz_lixian_xw）。

#### 5.3 删除会话历史 deleteChatSession（Query）

按 sessionId 删除该会话在 ES（sz_lixian_xw）中的全部历史任务，同时清理服务内存中的该会话。

```graphql
query {
  deleteChatSession(sessionId: "sess_58527fa3f6e445c79deda22e3c970486") {
    code
    message
    totalCount
    records
  }
}
```

返回 `records`：`{ sessionId, found(删除前条数), deleted(实际删除条数) }`。

| code | 含义 |
|------|------|
| 200 | 删除成功 |
| 404 | 该 session 无历史记录或已删除（可重复调用，幂等） |
| 409 | 该会话仍有进行中任务，需先调用 `/api/chat/cancel` 取消后再删（否则任务结束时会把记录重新写回） |
| 500 | sessionId 为空 / ES 异常 / 部分记录未删净（message 中给出剩余条数，可重试） |

说明：ES 8.x 与 RestHighLevelClient 7.x 存在响应体解析不兼容，删除请求可能已执行成功但客户端抛解析异常；服务端会识别该类异常，并以「删除后重新统计剩余条数」为准判定结果。

#### 任务状态字段 status

历史记录（ES: sz_lixian_xw）每条任务带 status：提问时即入库为 unning（content 为空），任务结束后由服务端更新为 end（正常结束，content 为完整答案）/ cancelled（用户取消）/ ailed（失败，content 为错误信息）。状态由 lixian-chat 服务自己更新，与前端是否断开 SSE 无关；服务进程异常退出时，进行中的任务会停在 unning。dd_date 为任务创建时间。
